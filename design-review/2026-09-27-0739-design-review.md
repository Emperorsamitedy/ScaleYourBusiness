## Inconsistencies

### P1 — Wrong token in high-visibility surface

#### Pressables are pills, and `.prop-btn` isn't one

- **Locations:** `app/globals.css:5110` (`.prop-btn`, `border-radius: 10px`) — rendered on /proposals, /content, /site, /chat, /history (Approve, Decline, Draft it, Preview the change, Send, Add goal…).
- **Offending value:** `border-radius: 10px; padding: 10px 22px` (≈41px tall).
- **Documented alternative:** `{rounded.full}` + 44px height — _"every button, status element, and toggle is a full pill… rectangles hold information, pills are things you press"_ (Shapes); `button-ghost` defines the recipe.
- **Why it matters:** the pill split is the reference's signature; a 10px-radius button on five screens erodes the system's single most recognizable rule.
- **Fix:** `border-radius: 9999px; padding: 10px 22px; min-height: 44px` (ghost-pill recipe; `.signal` variant keeps its border color).
- **To-do:** [ ] `.prop-btn` → full pill + 44px. _(one class, five screens — ~2 min)_

## New Patterns

### Promote — fills a real gap; add to DESIGN.md

#### The signal exception — `secondary` on approval controls

- **Locations used:** `.prop-btn.signal` (Approve buttons), `.prop-badge` (the one badge), `.ch-queued a` (queued-proposal link), `.prop-check` accent — /proposals, /content, /site, /chat.
- **Why it isn't an Inconsistency:** DESIGN.md forbids `secondary` as an action color, but `specs/ux-spec-v1.md` §3/§8 _mandates_ it — "Approvals are the only place `--signal` appears at full strength… colour means 'your turn'" — and CLAUDE.md gives specs precedence. The design system has a gap, not the code a bug.
- **Proposed token:** `colors.on-secondary: "#0B1220"`.
- **Proposed prose for `## Colors` / Do's & Don'ts:** _"The one sanctioned exception to `secondary`'s glow-only rule is the **approval signal** (ux-spec §8): controls that are literally the owner's turn — the Approve pill, the approval-count badge, the queued-proposal link — carry `secondary` at full strength, with `on-secondary` text on filled uses. Nothing else ever does."_
- **To-do:** [ ] Add `colors.on-secondary`. [ ] Add the exception prose. [ ] Amend the Don't to "…except the approval signal (see Colors)."

#### `button-compact` — the quiet utility pill

- **Locations used:** `.es-stop` (EmergencyStop's idle state on three screens).
- **New value:** ~28px pill, 13px label, muted until hover.
- **Why promote:** a persistent, deliberately low-emphasis utility control is a real class the system lacks; forcing 44px onto an always-present stop button would make it shout.
- **Proposed token:** `components.button-compact: { rounded: full, typography: label-md, padding: 6px 16px, height: 32px, textColor: on-surface-variant }` with prose: _"For persistent utility controls that must exist without competing (the emergency stop at rest). Never for advancing actions."_
- **To-do:** [ ] Add component def + prose; set `.es-stop` to 32px/13px.

#### `status-pill-outline` — the bordered state pill

- **Locations used:** `.prop-tag` (+`tr-*` verdict variants) — and the pre-existing `.conn-badge`, which established the idiom app-wide.
- **Why promote:** DESIGN.md documents only the filled `status-pill`; the transparent-with-hairline variant in `mono-sm` is the de-facto convention on every ops surface.
- **Proposed token:** `components.status-pill-outline: { backgroundColor: transparent, border: 1px outline, typography: mono-sm, rounded: full, padding: 3px 9px }` with prose: _"The machine-truth state pill — statuses, verdicts, read-only badges. Filled `status-pill` for human-facing state, outline for system-recorded state."_
- **To-do:** [ ] Add component def + prose.
